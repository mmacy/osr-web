# Content facts

- The adventure library (`server/library.py`) scans the bundled doc, the gitignored `adventures/` drop directory (files, [osr-forge](https://github.com/mmacy/osr-forge) output dirs, or symlinks to either), and `OSR_WEB_ADVENTURES` (colon-separated). Entries dedupe by file bytes. Ids are name slugs with `-2` suffixes on collision. The first entry (the bundled doc) is the default. The library screen's "Load from file…" button is the fourth way in. `POST /api/adventures` takes the browsed file's bytes and validates the document fully: envelope, model, and `validate_adventure`'s cross-reference walk (`library.add_adventure`). The scan itself stays metadata-only and never validates. The route then writes the bytes unchanged into the drop directory, deduping by digest against everything already scanned (`tests/test_library_upload.py`).
- **The drop directory is the only thing deletion may touch, in either direction.** `_sources()` flags each source for whether it *is* the drop directory, and the scan sets `drop_item` only on entries from a flagged source. That is why the bundled document stays undeletable even when `OSR_WEB_ADVENTURE` points inside `adventures/`, and why deleting an `OSR_WEB_ADVENTURES` entry returns a 422 rather than deleting anything. `drop_item` is the drop directory's own child, built from *unresolved* candidate paths: deleting a symlinked osr-forge run must remove the link sitting in `adventures/`, never the run it resolves to. The scan resolves everything else, which is why `entry.path` can't be the delete target. `remove_adventure` deletes each of the three shapes as what it is: a symlink is unlinked (run untouched), a `.json` file is unlinked, and a dropped directory is removed whole. For `<drop>/adventure.json` it deletes the file, not the directory. `entry.source_kind` crosses the wire so the client's confirmation can say which of the three shapes is being deleted. No path ever does (`tests/test_library_delete.py`).
- There are two directory overrides, both read per call (not at import) so tests can `monkeypatch.setenv` them. `OSR_WEB_ADVENTURES_DIR` **replaces** the `adventures/` drop directory (`library.adventures_dir()`). `OSR_WEB_SAVES_DIR` **replaces** the `saves/` directory that `POST /api/games/{id}/save` writes to and `GET /api/saves` lists from (`app._saves_dir()`). Every read and write goes through `_saves_dir()`, so the two routes can't disagree. Don't confuse the first with `OSR_WEB_ADVENTURES` (plural, no `_DIR`), which **appends** extra sources and leaves the drop directory in place. Both overrides take `~`, and both fall back to the repo default when unset or blank. Pointing both at empty directories is how a test or a screenshot run keeps the local library and saves off the title screen (`tests/test_paths.py`).
- The bundled document (`content/adventure.json`, override with `OSR_WEB_ADVENTURE`) is *The Cold Vein*: one dungeon, `cold-vein`, with two levels. Level 1 is 20×16 with 13 keyed areas and the entrance at (2,15). Level 2 is 18×14 with 8. The document is stamped `schema_version: 3` / `engine_version: "1.6.0"`, and both halves matter. An adventure envelope is checked but never migrated, and `Adventure` ignores unknown keys, so a pre-1.5.0 engine given a schema-2 stamp on a document that includes `items`/`triggers`/`quests` would silently drop those sections and load an adventure that can't be won, instead of refusing the document. The engine version is 1.6.0 because the document names its objectives (`ObjectiveSpec.name`). osrlib 1.5.0 would load the document and then show both objectives by their slugs. `content/README.md` is the document's provenance note and its feature index. Keep that file true when you change the document.
- The document has **six door edges**: plain at level 1 `7,11:north`, stuck at level 1 `13,10:north` and level 2 `2,4:north`, locked at level 2 `4,4:north`, secret at level 1 `17,5:north`, and **gated** at level 1 `11,3:north`. Playing the default document therefore exercises the door UI (open/force/listen/pick, arch rendering in the viewport). The document also contains two room traps, a treasure trap, eight authored caches, both `AreaTreasureSpec` branches (`unguarded` and `letters: ["C"]`), a construction trick, and a custom feature.
- The document's authored layer is two bundled items, one gated door, one trigger, one concluding quest, and **five `guidance` blocks**: both levels' ambient `LevelSpec.guidance` slots, the quest's block, the gate's, and the trigger's. Every guidance carrier (a level, quest, objective, trigger, or gate whose `guidance` block the narrator's guidance channel reads) except the objective is therefore exercised against the default. The objectives have none, deliberately. The objective carrier's window (the runs its block steers) is pinned in `tests/test_narration.py` against a doctored copy. All five blocks are steering rather than script, and none restates a display beat. `content/README.md` says what each one steers. `verrow-token` ("Saint Verrow's token") sits on the `offering-ledge` cache in area 9. The gate on `11,3:north` is a **non-consuming** `has_item` on the token, with authored `refusal`/`success` beats, and it opens area `21` ("The saint's cupboard"), a side room that is never the only route to anything. The toll (`consumes: true`) form is exercised in tests against a doctored copy written to a temp directory rather than shipped. Level 1's area ids are `1`-`12` plus `21`, because `13`-`20` are level 2's. `adit-draught` is a non-repeatable `area_entered` trigger on level 1 area 1 with **no consequences**. The entrance cell is inside that area, so the trigger fires on `enter_dungeon` itself, adds one prose journal line, and costs no time and no dice. That is why the scripted route to the first fight is unmoved. A gated *transition* would lose its success beat unless it crosses a level or dungeon boundary (a same-level transition emits no arrival event), which is why the bundled gate is a door.
- The quest is `the-day-book`. It is activated by `dungeon_entered` on `cold-vein`, so the transcript announces it at the adit mouth, beside `adit-draught`. (A quest with no `activation` is active from session start with no activation beat, so nothing would ever announce it and it would stand silently in `view.quests`.) It is completed by `completion: "all"` over two visible objectives: an `item_acquired` clause on the second bundled item, `captains-day-book`, then `town_entered` with a `has_item` on it. **The `item_acquired` objective is what prevents a short-circuit.** `has_item` alone is satisfied by a relic merely carried in. Matching is edge-triggered, so on a homecoming without the book the interpreter checks the clause once, the `has_item` condition fails, and the objective waits for the *next* arrival rather than retrying. The relic lies on the `captains-board` cache in area 18 ("The cold face"), behind the two zombies keyed there and behind no lock or gate. Rewards are `grant_coins` 100 gp then `award_xp` 200, both to `@party`, which expands **per living member**. The payment is per head, which is how hook 1's "pay twice over" reads at a table. Both rewards land after the session is already `victory`, so both have to be terminal-legal. Coins and XP are. Spawns and placements are not. Neither objective is hidden and neither has an `offer` beat (an objective's `offer` is the line its reveal shows, and no reveal fires here), so the default document never exercises `objective_revealed`. Proving it is the barrow fixture's job (`tests/assets/barrow-adventure.json`, *The Barrow of the Ninth*). The quest adds two transcript lines and one journal entry to `enter_dungeon` and moves no dice. The scripted route to the first fight holds.
- Level 2 has no entrance of its own. The `stairs_down` on level 1 at (18,1) lands the party at level 2 (2,12) facing north, and the matching `stairs_up` sends them back to (18,1) facing west. Both directions are authored and both work. A level with no `entrance` is normal. The state payload's `dungeons` list drops only a *dungeon* with no entrance on **any** level.
- Level 1's wandering chance is authored at `0`-in-6, so the SRD level-1 table (on which a 1 is 1d8 AC 2 acolytes) can't cut the opening rooms short. That doesn't mean no checks at all: `wandering_check` adds +1 for noise since the last check, and a battle is noise, so a check can still fire (and does) in the two turns after a fight. Level 2 is RAW `1`-in-6 every two turns, and encounters do happen there.
- Some osr-forge documents contain several dungeons in one adventure. The town panel renders one enter button per dungeon, so don't assume a single dungeon anywhere. The bundled document has one (`cold-vein`).
- `TownSpec.services` is prose for the front end and nothing else. The bundled town, Cinderhope, lists four. Every town command (`purchase_equipment`, `purchase_healing`, `sell_treasure`) still works in a town that lists none, because the engine gates the commands on mode, not on the services list.
